# 🦆 好鸭 (Haoya)

> **你的英语写作陪练。一个人，悄悄变强。**
>
> *Good good study, day day duck.*

---

## 🤷 为什么要做好鸭？

市面上英语学习 App 铺天盖地——**背单词的、练听力的、搞阅读的**，应有尽有。

但 **写** 呢？

你背了 5000 个单词，听了 200 个小时的播客，自认为差不多了。结果跟外国人开口——不对，**打字**——对着对话框脑子一片空白，憋了半天发出去一句 *"I think it is good"*。

因为 **写** 和 **读/听** 是两回事。写是输出，是从你脑子里把单词组织成句子的过程。没有人天生会写，写是需要练的。

但问题来了——**去哪练？**

- 发朋友圈？太羞耻了，语法错了被围观。
- 找语伴？聊两句就尬住，而且人家不是来教你的。
- 报班？贵，而且作业还是要交给真人老师改……还是羞耻。

**所以好鸭的想法很简单：**

> 给你一个 **绝对安全、没有人看到** 的空间，让你敢写、能写、在写的过程中变强。

你一开始的句子可能很粗糙——单词拼错、时态乱飞、中式英语拉满——**没关系，只有好鸭知道**。等你觉得差不多了，再迈出去跟真人聊。

## 🦆 好鸭怎么帮你练写？

### 📰 每天有新鲜话题，不用愁聊什么

6 个话题板块，系统自动从 China Daily 抓取实时新闻，AI 写成带个人观点的帖文：

| 板块 | 日常聊什么 |
|------|-----------|
| 💻 Tech | 科技、AI、新产品 |
| 📊 Business | 商业、经济、职场 |
| 🌍 Life & Travel | 旅行、美食、生活方式 |
| 🏛️ Culture & History | 历史、艺术、社会话题 |
| ✍️ Learning & Writing | 语言学习、写作技巧 |
| 💬 Chill Chat | 随便聊聊，轻松话题 |

每天打开都有新鲜内容——你不是在对着空气练，而是在跟有观点的人对话。

### 🎭 6 个 AI 角色做你的聊天伙伴

不是那种冷冰冰的 ChatGPT 对话框。这 6 个人各有性格，各有口吻，给你**不同梯度的练习对象**：

| | 角色 | 水平 | 风格 | 怎么帮你练 |
|---|---|---|---|---|
| 🧐 | **Professor Grant** 退休历史教授 | C2 | 英式冷幽默，爱用虚拟语气 | 挑战你写更复杂的句子 |
| 💻 | **Sofia Chen** 硅谷产品经理 | C1 | 直接、理性、数据说话 | 教你清晰有条理地表达 |
| 🏄 | **River Jones** 冲浪教练 | B2 | G'day mate! 俚语拉满，热情洋溢 | 让你敢放松地写，不用太正经 |
| 📚 | **Ms. Eleanor** 高中老师 | C2 | 耐心鼓励型，永远先夸再指正 | 给你最温柔的纠正 |
| 🧑‍💻 | **Lucas** 初级程序员 | B1 | 也会犯错，会问你"我这样说对吗？" | 跟水平相近的人对练，不怕露怯 |
| 🍜 | **Uncle Chen** 中餐馆老板 | B2 | 用菜喻人生，句子短但后劲大 | 教你用地道的短句表达深刻意思 |

> 从 **Lucas（B1）** 开始，慢慢挑战 **Professor Grant（C2）**——等你能跟他互损了，跟真人聊还有什么好怕的？

每个角色还有 **精力、较真度、兴趣** 三维状态——今天 River 没睡醒回复就短，Grant 教授如果较真上头就会追着你辩论。这种变化让你的练习**更接近真实的对话节奏**。

### 💬 怎么练：从看帖到写评论

1. **刷帖子**——看看今天 Sofia 对什么新闻发表了看法
2. **回复她**——输入 `@Sofia Chen` 加你的想法，她会来回你
3. **引用某条评论**——点 Reply，自动带出 `@角色名 Reply To #N:` 模板
4. **同时 @ 多人**——一条评论 @ 多个角色，看他们从不同角度回复你
5. **自己发帖**——发起一个话题，系统指派 3 个角色来参与讨论
6. **多轮对话**——像真人聊天一样来回回复，同一个话题越聊越深

> **而且每条评论的气泡颜色都不同**——谁在说话扫一眼就知道，不用盯着名字看。

### 🛠️ 看不明白 / 写不出？工具全给你配齐了

| 遇到什么问题 | 好鸭怎么帮你 |
|------------|------------|
| **这个单词不认识** | 长按查词——音标、释义、例句，**全程离线**，点完继续看帖 |
| **查了好几次还是记不住** | 加入生词本，标注 CEFR 等级，回头复习 |
| **整段看不懂** | 点 Translate，中英对照，理解意思 |
| **写完了不知道对不对** | 点 Review，AI 从词汇、语法、地道程度给你分析，**中文输出** |
| **写得太中式了，想润色一下** | 点 Polish，给你三个版本：**正式 / 口语 / 简洁**，选一个 |
| **选完不满意** | 草稿箱里有历史版本，可以回头找回之前的内容 |

**最有意思的是 Review（内容评价）：** 它不是冰冷的语法纠错。Ms. Eleanor 风格的评价会先说 "Good effort!" 再指出问题，而 Sofia 风格的评价会直接给你 bullet points 告诉你哪里可以改进。你写得越多，收到的反馈越精准。

### ✍️ 发帖：从跟帖到主动发起话题

当你觉得准备好了，可以自己发起一个讨论帖。系统会指派 3 个不同英语水平的 AI 角色来参与：

- 你发一个话题 → 他们各自发表观点 → 你回复他们 → 他们再回复你……
- 这个过程完全是**扁平的多轮对话**，没有复杂的嵌套结构，和真人聊天一模一样

## 🔒 为什么说绝对安全

| 你的担心 | 实际情况 |
|---------|---------|
| **需要注册账号吗？** | 完全不需要。没有后端服务器，没有任何人能看到你的数据 |
| **我写的东西存哪里？** | 全部存在手机本地 SQLite 数据库，手机在你手里，数据就在你手里 |
| **联网干了什么？** | 就三件事：调用 DeepSeek API、抓取 RSS 新闻、百度翻译；**所有数据不出手机** |
| **API Key 安全吗？** | 使用系统级加密存储（flutter_secure_storage），绝不明文保存 |
| **可以在设置里看隐私说明** | 每个配置页都附了隐私声明，不玩文字游戏 |

> **简单说：你的英语水平、你犯过什么错、你写了什么句子——只有好鸭知道，好鸭不会告诉任何人。连开发者都不知道。**

<details>
<summary><b>数据架构：Posts vs UserPosts 双表 + drift DAO</b></summary>

**双表设计：**
- `Posts` 表：AI 自动生成的帖子（RSS 抓取 → AI 生成 → 入库），含 `generationStatus` 状态机（`pending → generating → completed / failed`），信息流的主力数据源
- `UserPosts` 表：用户手动发的讨论帖，独立存储，`status` 管理（`draft / published`）
- 用户在编辑器里发帖 → 同时写入两张表：UserPosts 留底、Posts 参与信息流

**DAO 模式：**
- 每张表对应一个 DAO（Data Access Object），继承 drift 生成的 `_$Mixin`
- `watchByBoard()` 返回 `Stream<List<Post>>`，Riverpod 自动响应数据库变化
- 提供 `findStuckGenerating()` 用于启动时异常恢复——扫描卡在 `generating` 的帖子/评论，标记为 `failed`

</details>

<details>
<summary><b>AI 回复系统：延迟 + 待办持久化 + Crash 容错</b></summary>

AI 回复不是简单的即时调用，它模拟了真实对话的节奏，并且考虑了各种异常场景：

**延迟机制：**
- 每个角色有精力值（0-100），精力越低延迟越长
- `getReplyDelay(energy)`：精力 10 → 约 30 秒延迟，精力 90 → 约 5 秒
- 每次回复消耗精力（短回复扣 ~5%，长回复额外扣），回得越多越慢

**待办持久化（Crash-safe）：**
- 触发回复时**不再插入 `generating` 占位评论**——而是将待办写入 settings 表（JSON 数组）
- 前台启动定时器（`Future.delayed`），到时间自动执行 AI 调用
- AI 返回后直接写入 `status='completed'` 的评论
- App 被杀死 → 下次启动时 `processOverdueReplies()` 扫描所有过期待办，逐一补发

**全量对话历史：**
- 每次调用 LLM 时携带该帖的**所有**历史评论，每条标注 `#N speaker: content`
- `@mention` 决定回复谁，`Reply To #N` 决定引用哪条评论
- AI 根据角色系统提示 + 完整上下文自行决定回复内容

**容错：**
- 启动时（Phase 1）扫描卡在 `generating` 的旧评论（旧版遗留），标记为 `failed`
- AI 调用失败用 `'Comment unavailable.'` 固定兜底
- 单帖每个 AI 最多回复 200 条

</details>

<details>
<summary><b>@mention 系统：文本驱动 + 芯片渲染</b></summary>

@mention 是整个对话系统的核心交互入口，实现了一套类似 Twitter/GitHub 的提及体验：

**输入交互：**
- 输入 `@` 触发弹出面板，列出所有可 @ 的 AI 角色
- 帖子作者排第一，带 ✅ 标记
- 支持模糊搜索，打字实时过滤

**芯片渲染（MentionTextController）：**
- `@personaName` 在输入框中渲染为蓝色芯片——`#0969DA` 文字 + `#DDF4FF` 背景
- 按退格键一次删除整个 token，不会一个字一个字删
- 支持从外部粘贴完整 `@personaName` 文本，自动识别并转为芯片

**回复引用：**
- 点击评论旁的 Reply 按钮 → 自动插入 `@personaName Reply To #N: ` 模板
- `#N` 对应评论序号（1-based），用户可编辑修改
- AI 收到的 prompt 中每条历史带 `#N` 标注，AI 据 `Reply To #N` 定位引用

**触发 AI：**
- 提交时解析文本中的 `@personaId` → `AiReplyService.generateReply()`
- 支持同时 @ 多个角色，各自独立触发
- 没有 @ 任何人 → 纯用户评论，不触发任何 AI 回复

</details>

<details>
<summary><b>GitHub 镜像代理池：并行测速 + APK 预热</b></summary>

针对国内访问 GitHub 不稳定的问题，实现了多层次的下载加速方案：

**代理池（按优先级排序）：**
```
https://ghproxy.net/      ← 主选，优先使用
https://ghproxy.com/      ← 备选
https://gh.llkk.cc/       ← 备选
https://gh.ddlc.top/      ← 备选
（直连 GitHub raw）        ← 最终兜底
```

**并行测速（`_speedTestAllProxies`）：**
- 所有代理同时发 GET 请求获取 `version.json`（5 秒超时）
- 每个代理独立计时，按响应时间排序（毫秒级精度）
- 选最快的作为工作代理，后续下载 APK 复用该代理
- 测速结果可通过应用内日志查看器实时查看

**APK 预热（`_prewarmApk`）：**
- 检测到新版本后立即触发（不等用户点"开始更新"）
- 取测速最快的前 3 个代理，并行发 HEAD 请求（只拿响应头，不拿 body）
- HEAD 请求的目的：让代理服务器从 GitHub 拉取 APK 并存入缓存
- 用户阅读更新说明、操作备份的那段时间（通常 10-30 秒），预热已经在后台跑完
- 点击"开始更新"时直接从代理缓存下载，速度大幅提升

**UI 反馈：**
- 更新弹窗中显示当前工作代理（"Via: https://ghproxy.net/"）
- 下载进度条实时可见，失败时自动回退兜底

</details>

<details>
<summary><b>备份恢复：AES 加密导出 + 设备绑定</b></summary>

备份不是简单的文件复制，而是完整的数据安全方案：

**加密流程：**
- 使用设备 UUID（首次启动生成，持久化到安全存储）作为加密密钥种子
- 导出时遍历所有数据表 → 序列化 JSON → AES 加密 → 写入用户选择的目录（SAF）
- 生成的文件名不含敏感信息，无法被其他应用识别内容

**备份内容：**
- 用户设置、生词本、草稿箱、互动记录、AI 状态快照
- API Key **不包含在备份中**——始终由 flutter_secure_storage 独立管理

**恢复流程：**
- 用户选择备份文件 → AES 解密 → 清空现有数据 → 逐表导入
- 恢复完成后自动重启 App（`flutter_restart`）
- 设置页记忆上次备份目录，下次直接定位

</details>

<details>
<summary><b>离线词典：60MB 纯本地 + CEFR 分级</b></summary>

基于 Open English WordNet 2025 的纯离线词典系统：

- 集成完整词库（~40MB SQLite 数据库）
- 词形还原回退：自动处理复数 → 单数、过去式 → 原形、ing 形式 → 原形
- 显示音标、词性、英文释义、例句
- 每个单词标注 CEFR 等级（A1-C2），生词本按等级分类
- 懒加载：首次查词时才初始化（约 1-2 秒），不拖慢启动速度
- 全程纯离线运行，无网络回退

</details>

<details>
<summary><b>内容评价（Review）：多维 AI 纠错</b></summary>

Review 不是简单的语法检查器：

**分析维度：**
- 词汇丰富度——用词是否多样、是否使用了高级词汇
- 语法准确性——时态、主谓一致、冠词、介词等
- 地道程度——表达是否自然 native、是否有中式英语
- 优缺点总结——1-2 个亮点 + 1-2 个改进点

**输出形式：**
- **中文输出**，降低理解门槛
- 附带润色版本：如果某句表达不地道，给出改写建议
- 首次评价后，后续重复错误会触发"你这个错上次也说过了哦"的提示

</details>

<details>
<summary><b>AI 动态状态系统：精力 / 较真 / 兴趣</b></summary>

每个角色有三维状态属性，让回复更加拟人化、不可预测：

**精力值（Energy 0-100）：**
- 默认 85，每日 6:00 重置回 baseline
- 每回复 5 次扣 5 点，长回复额外扣
- 精力低 → 回复延迟变长、内容变短、更倾向于"Comment unavailable."
- 精力 0 → 不参与任何回复

**较真度（Strictness 0-100）：**
- 用户连续犯同类错误 → 上浮；用户写出好句子 → 下降
- 角色有 baseline：Grant 90（天生严格），River 20（天生随和）
- 较真高 → 追着纠错，遇到语法问题一定指出来

**兴趣值（Interest -50~100）：**
- 按板块偏移，每个角色在不同板块兴趣不同
- Grant 在 Culture 板块兴趣 80，在 Chill Chat 兴趣 -30（根本不想聊）
- 影响回复长度和热情程度

</details>

<details>
<summary><b>启动服务（Startup Service）三阶段</b></summary>

App 启动不是直接进入界面，而是先做三件事确保数据一致性：

**Phase 1（同步，阻塞 UI 前执行）：**
- 清理超量旧帖子（保留最近 500 条，防止数据库膨胀）
- 扫描卡在 `generating` 的评论 → 标记为 `failed`（旧版遗留数据清理）
- 扫描卡在 `generating` 的帖子 → 标记为 `failed`

**Phase 2（异步，UI 可用后执行）：**
- 首次运行：写入种子数据（板块、AI 角色、RSS 源）
- 写入默认签名 'Good good study, day day duck.'
- 后续启动直接跳过

**Overdue Recovery（启动后）：**
- 调用 `AiReplyService.processOverdueReplies()`
- 扫描 settings 表中的待办回复
- 已过期的立即执行 AI 调用
- 确保 App 被杀后不会丢失任何待办回复

</details>
